# P5：独立审核待办

版本：`0.3.0-dev.24`。本轮在已推送的 `.23` Cloudflare 重建基线上继续业务开发，账号系统继续延期，不变更生产准入和云资源。

## 用户路径

发布者按现有流程上传、检查并创建版本。独立审核者连接自己的身份后，在“独立审核待办”点击“读取审核待办”，选择“查看并审核”，读取服务器当前版本事实后提交批准或拒绝。无需从发布者手工复制版本 ID；已知 ID 的原入口仍保留。

本地体验使用 10001 创建、10002 审核。AV、身份签发及部署准入的模拟边界与 [本地体验](P5_LOCAL_TRIAL.md) 相同。审核列表不是包体预览或恶意内容安全证明。

## API 与权限

`GET /v1/reviews?limit=20&after=<uuid>` 返回 `{ items, nextCursor }`。每项复用现有版本事实，并附加 `owner`；每页默认 20、最多 50 项，UUID keyset 排序，不提供任意筛选或全文搜索。

- 必须通过原身份验证，并在部署者的 `REVIEWER_PRINCIPALS` 名单中；非审核者返回 404，缺失/错误配置返回 503。
- 每页重新检查名单，只返回他人 `pending_review` 且资源仍为 `draft` 的版本。owner、成员关系和客户端角色不赋予审核列表权限。
- 批准、拒绝、撤回或资源删除后，后续读取不再返回该待办。分页不是一致性快照，新插入且排序在游标之前的条目需要刷新第一页。
- 绑定变化的待办仍可被看到并拒绝，但批准继续受完整快照校验限制。列表响应不是审核授权凭据；点击后重新读取版本，最终决定继续由既有 CAS 和审计事务保护。
- D1 失败返回脱敏 503；不把错误写成空队列。请求日志只增加固定 `reviews` 分类，不记录主体、游标或版本内容。

新增 `db/0007_review_queue.sql` 只建立 `versions(state, id)` 索引，不改写历史状态。本地新库与候选包含该迁移；没有应用到既有云库，也不删除旧本地数据。未来云部署需单独获准并增量应用。

迁移顺序为旧六份迁移/业务数据 → 由 D1 迁移记录保证 `0007` 只应用一次 → 新旧查询继续工作。代码回退可直接使用上一候选并保留新增索引，无需删索引或恢复数据；没有破坏性收缩步骤。聚焦测试在已有资源、上传、检查、版本及审计记录上应用索引，逐项比较前后数据，并验证原 owner 查询和审核继续可用。

## 前端边界

复用原共享行、按钮、文本节点和颜色，不增加依赖或新的静态模块。列表只保留当前页，长内容在现有内部滚动区显示。文本不进入 `innerHTML`。

读取时清除旧待办；失败、取消与空结果分别显示。身份切换清空队列与游标，旧请求不得写入新身份状态。审核决定成功后移除本页对应项；其他人的并发变化通过刷新读取，不建设推送、后台轮询、批量批准或审核分派。
