# P5：资源管理页面操作

版本：`0.3.0-dev.25`。目标是在现有私有工作区内完成 owner 日常资源管理，不要求手工构造 API 请求；本轮不接账号系统，不部署云资源，不改变生产准入。

## 用户路径

owner 选择活动资源后，可修改标题、关闭资源，或输入指定 `PrincipalRef` 查询当前目录读权限，再授予或撤销。改名、关闭和权限变更均先显示影响范围并要求确认；取消不写入。每次成功变更后重新读取资源目录和当前工作区，查询到的旧成员 revision 不会继续使用。关闭是逻辑关闭：活动目录和新下载停止，历史审计与文件保留，不提供恢复入口。

目录读成员只能看到被授权资源的目录元数据，不能管理资源、读取隔离上传或版本，也不能据此下载包体。包体下载仍需独立的发布授权。页面在非 owner、未选择资源或非活动资源时禁用管理控件。

## API 与一致性

新增 `GET /v1/resources/{id}/members/{principal}`，仅活动资源的 owner 可查询**指定主体**的 `{ resourceId, principal, active, resourceRevision }`；不提供全体成员枚举。无身份返回 401，非 owner、无关主体或已关闭资源返回 404，非法主体或查询参数返回 400。D1 的同一查询读取权限事实和资源 revision；查询本身不产生审计或修改资源。

写入继续使用已有的 `PATCH /v1/resources/{id}`、`DELETE /v1/resources/{id}` 与成员 `PUT`/`DELETE`：幂等键、预期 revision、D1 原子事务和审计逻辑不变。网络失败或取消后的写入结果未知，不自动换键重试；409 冲突不猜测新 revision。资源 revision 变化使已有版本绑定失效，审核/发布/新下载依旧由服务器当前事实判定，历史批准和文件不重写。

Web 的资源管理状态只属于当前身份与当前资源。身份或资源切换、资源 revision 变化时清除指定成员查询结果；身份清除还清空“新资源标题”草稿，避免上一主体输入留在下一主体页面。所有服务器文本写入 `textContent`，不进入 `innerHTML`。

## 验证与边界

- 后端聚焦覆盖权限查询、授予/撤销、无权限/错误输入/关闭资源、旧 revision 冲突；前端聚焦覆盖确认、取消、幂等键、未知写入、状态切换和迟到响应。
- 本地独占体验的真实浏览器从空库完成 10001 创建/改名、查询并授予 `trial:10003`、10003 只读访问、10001 撤销后成员目录消失、10001 逻辑关闭后 owner 目录消失。390px 视口 `scrollWidth` 等于视口宽度，控制台无错误；体验状态仅在 `linshi`，不触碰旧体验数据。
- 最新完整测试、格式、类型、行数、依赖审计、构建及提交身份以本轮交付回执和 Git 记录为准。上述本地事实不证明真实账号、实际 AV 安全、云部署或生产分发；延期的原生安全与网络边界验收仍未关闭。
