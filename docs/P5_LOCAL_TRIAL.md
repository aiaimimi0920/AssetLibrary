# P5：虚构编号的本地全流程体验

版本：`0.3.0-dev.23`；验证日期：2026-10-06 UTC。

用户确认独立账号服务尚未部署，要求先使用虚构编号跑通 AssetLibrary，再接入正式账号。
本批提供可手测的本地入口，不部署账号系统，不把真实账号合同继续作为本地业务体验的前置。

## 直接启动

在 AssetLibrary 仓库中运行：

```powershell
rtk proxy pnpm trial
```

命令先执行正常 Worker dry-run 构建，再启动仅监听 `127.0.0.1` 的体验服务。
打开输出中的 `LOCAL_TRIAL_READY http://127.0.0.1:<port>`。不需要注册、验证码、
账号服务或手工粘贴 JWT，也不需要 Docker、Cloudflare 凭据或新增依赖。

| 虚构编号 | 主体 | 建议用途 |
| --- | --- | --- |
| 10001 | `trial:10001` | 创建资源、上传、发布、下载授权和下架 |
| 10002 | `trial:10002` | 独立审核者，唯一的审核配置主体 |
| 10003 | `trial:10003` | 被授权下载的用户 |
| 10004 | `trial:10004` | 未授权对照用户 |

编号不是手机号。每个编号是不同主体，并非全局管理员；业务权限仍由原 D1 事实决定。
普通用户可以创建自己的资源，不允许改别人资源；owner 不因为使用体验入口而取得自审权限。
身份令牌为仅本轮有效的临时 RSA 签名，最长 900 秒；过期后重新连接相同编号即可。

## 手测顺序

1. 选择 **10001** 并连接，点击“下载双 PNG 示例包”，创建 Art 资源。
2. 上传示例 ZIP，选择“格式 + ClamAV 内容检查”。本地替身会明确模拟 AV；
   真实 ZIP/PNG/CRC/摘要和预算检查仍执行，不能上传任意脚本或其他格式。
3. 后台每两秒处理有界队列，也可点“立即执行检查队列”。查询检查为 `passed` 后创建版本。
4. 切换 **10002**，在独立审核区点击“读取审核待办”→“查看并审核”并提交决定；也保留按版本 ID 读取入口。待办列表从 `.24` 起提供，详见 [审核待办](P5_REVIEW_QUEUE.md)。
5. 切回 **10001**，选择原资源，发布已批准版本，再进入“管理发布”。
6. 输入下载主体 **`trial:10003`**，查询后授予下载权限。
7. 切换 **10003**，读取“我的下载资源库”，下载并保存经过长度和 SHA-256 核对的 ZIP。
8. 切回 **10001** 撤销下载权限；10003 的新下载/续传及旧票据应拒绝。
   owner 下架后，公开目录不再显示该发布，owner 自己也不能取得新下载票据。

页面保留生产准入阻断字段，包括 `SCANNER_CLOUD_NOT_VALIDATED`。
它们不是体验失败：只在本地体验器中假设部署准入；没有将生产事实写成通过。
“立即执行检查队列”完成也不表示每项检查通过，必须读取实际 inspection 状态。

## 真实执行与模拟边界

真实执行：原 Web 界面、RS256 校验、D1 授权/CAS/幂等和审计、R2 字节、上传和
格式检查、独立审核、发布/目录、票据、流式下载、Range、撤销/下架。

模拟：账号签发者、AV clean 事实及部署准入。不运行 ClamAV，不提供恶意文件安全保证。
请只使用无害体验素材。本轮没有生产安全、网络隔离或云正向分发验收结论。

`scripts/trial/bundle.mjs` 先逐项验证普通候选 SHA-256，再对唯一确定的部署门禁
函数做**内存中**替换，原文件不改写。形状不匹配或重复时立即拒绝启动，不做宽泛
文本替换。原 `versionSafety`、权限和状态检查保留，`cloudValidated` 仍为 false。
临时 signer、模拟 scanner 和登录路由只在 Node 本地体验器装配，不进入生产 Worker 模块。

## 生命周期与保护

- 每次启动在 `../../linshi/assetlibrary-local-trial-*` 创建新的独占 D1/R2 状态。
  不删除、不迁移、不覆盖旧体验目录；本版本不提供旧体验目录重开参数。
- 用页面“停止本地体验（保留数据）”或启动终端 Ctrl+C 关闭本轮服务。
  先停止 HTTP/定时任务，再 dispose 所属 Miniflare/workerd；状态目录写入 `closed.json`。
- Host/Origin/Fetch Metadata 检查、同源 JSON + 自定义头保护本地登录/队列/停止入口。
  不开启 CORS，不接收任意主体、角色、监听地址或云配置。
- 主/模拟 Worker 的默认出站 fetch 拒绝；这是本地工具配置，不替代延期的生产网络边界验收。
- HTTP 转发最多 8 个并发请求、16 MiB 请求体、130 秒请求超时。上传和下载使用流式转发，
  不在代理中整包缓冲；只允许明确的业务和静态路径，不转发 Miniflare 内部控制路径。
- 私钥不落盘；JWT 不写日志或浏览器存储；切换编号先清除旧主体、视图并取消旧请求。
- `session.json` 仅保存 PID、地址、候选摘要和状态路径等非秘密信息。

## 本轮发现并修复的问题

1. 真实 workerd 对未知长度响应使用流式传输，HTTP 未保留 `Content-Length`。
   旧前端因此拒绝完整的包体。现在允许缺失该头；若提供则必须为规范正整数且与元数据
   匹配。每个 chunk 仍受大小上限约束，最终实际字节数和 SHA-256 都匹配才返回 Blob。
   截断、超长、损坏和取消仍拒绝，不伪造响应头或引入服务端整包缓冲。
2. HTML `pattern` 使用 Unicode sets (`v`) 语义，未转义的 `-` 导致浏览器语法错误。
   原位转义并验证合法/非法版本标签；服务端版本合同未变化。
