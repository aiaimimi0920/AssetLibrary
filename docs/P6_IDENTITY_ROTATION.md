# P6：固定公钥轮换与本地配置恢复

## 范围和完成边界

`0.3.0-dev.19` 增加部署者固定公钥集，并验证同一份真实本地 Worker/D1/R2
状态上的“旧钥 → 重叠 → 撤旧 → 配置回滚”。没有新增账号服务、签发接口、
数据库迁移、外部身份发现、云配置写入或认证旁路。

这是 P6 的本地身份配置切片，不是 P6 Cloudflare 退出验收。测试使用内存中
生成的合成签名者，不证明真实账号可登录。原生组件安全风险和网络边界按用户
要求延期，生产发布/分发仍拒绝 `SCANNER_CLOUD_NOT_VALIDATED`。

后续 `.22` 已按明确授权在同包隔离 Cloudflare 环境验证合成身份的单钥、双钥
重叠、撤旧、可信重叠回滚、非法配置和恢复；18 条业务/就绪结果及配置版本日志
关联通过，原公开身份配置已恢复，入口/cron 关闭、D1/R2 保留。详细证据及真实
失败见 [P6 同包云验收](P6_CLOUD_RECOVERY_VALIDATION.md)。这不改变本地 `.19`
的历史事实，也不等于独立账号服务的真实签发、登录或完整 P6 退出。

## 当前身份合同

`AUTH_ISSUER`、`AUTH_AUDIENCE` 必须配置，且必须恰好选择一种公钥配置：

| 配置 | 格式与边界 | JWT 的 `kid` |
| --- | --- | --- |
| `AUTH_PUBLIC_JWK` | 一个 RSA 公钥 JSON，最多 4096 字符 | 可以缺失；显式提供时必须与公钥的 `kid` 相同 |
| `AUTH_PUBLIC_JWKS` | `{"keys":[...]}`，最多 16384 字符，1–4 把公钥 | 必须存在并精确命中，不尝试其他钥匙 |

两种配置同时存在，即使其中一个为空，也失败关闭；切换时必须移除另一项。
JWKS 不接受 URL、额外顶层字段、空集合、重复 `kid` 或重复 RSA 公钥材料。
其中任一公钥损坏，整个配置拒绝，不忽略坏钥或退回备用路径。

每把公钥只接受 `kty`、`n`、`e`、可选的 `kid`、`alg`、`use`、`key_ops`：

- `kty` 必须是 `RSA`；`n`/`e` 必须是规范的无填充 Base64url 无符号整数。
- 模数限制 2048–4096 位且为奇数；指数是 1–4 字节的奇数且不小于 3。
- `alg` 若存在只能为 `RS256`；`use` 若存在只能为 `sig`。
- `key_ops` 若存在必须恰好为 `["verify"]`。
- `kid` 若存在必须是 1–128 个 ASCII 字母、数字或 `._:-`；JWKS 中必须存在。
- 拒绝私钥参数、证书和其他字段；不要把整个 provider 的发现文档直接粘贴进来。

仍只验证 RS256、固定 issuer/audience、`sub`、`iat`、`exp` 和可选 `nbf`。
令牌最长 900 秒，无 clock tolerance。`PrincipalRef` 仍来自 `sub`，不包含
`kid`，不接受客户端角色或主体头；D1 继续决定业务权限。轮换不改变主体命名
空间、issuer 或 audience，也不迁移/重置业务数据。

缺少或非法配置返回脱敏 `503 IDENTITY_NOT_CONFIGURED`；未知/缺失 JWKS `kid`、
错误签名、算法或 claims 返回 `401 UNAUTHENTICATED`。配置先于 Bearer 校验，
因此坏配置下没有令牌也返回 503。`/healthz` 仍只是存活，不表示身份/DB 就绪。
错误响应不包含公钥 JSON、JWT 或内部导入错误。

所有公钥逐请求校验和导入，最多 4 把；没有全局缓存、跨请求旧 key 状态或网络
密钥查询。没有根据 JWT `jku`、嵌入 `jwk` 或证书头联网/信任新密钥。尚未做生产
延迟/容量测量，不承诺零开销、零停机或云端配置瞬时生效。

## 正常轮换 runbook

以下是部署操作者在对应授权后的步骤；`.19` 本地批次未执行云配置切换。后续
`.22` 云切片只使用合成 signer，没有操作真实外部账号的签发密钥或登录流程。

1. 保存当前可信的**公开配置**和版本，确认 issuer、audience、`sub` 映射固定。
   私钥由独立签发者持有，不进入 AssetLibrary、日志、包或浏览器。
2. 若当前公钥与令牌均没有 `kid`，先在单钥配置给旧公钥添加固定 `kid`。单钥
   模式仍接受未标 `kid` 的存量短期令牌。然后让签发者为新令牌标同一个旧 `kid`。
3. 停止签发无 `kid` 令牌后，至少等待最后一枚此类令牌的 900 秒寿命和实际部署
   传播窗口。确认客户端均取得带标签的令牌，再切换 JWKS；否则存量无标签令牌
   会被明确拒绝，而不是自动猜钥。不要通过扩大 TTL 或容差绕过过渡。
4. 发布只含旧、新公钥的固定 JWKS，并移除 `AUTH_PUBLIC_JWK`。在实际环境确认
   两把钥都可对同一主体验证、业务权限不变后，签发者再开始用新 `kid` 签发。
   不要在 Worker 仍只有旧公钥时先签发新钥令牌。
5. 停止旧钥签发后，等旧令牌最长寿命和实际传播窗口，移除旧公钥。对新的 HTTP
   请求验证：旧令牌 401、新令牌成功、幂等重放不增加 revision 或审计。
6. 普通配置失误可以恢复上一个仍可信的重叠配置；已泄露密钥不得恢复。重新放入
   旧公钥就会重新信任它，本实现没有永久撤钥黑名单或“回滚但保持旧钥禁用”能力。

撤钥只影响采用新配置的后续认证。已经通过身份校验、正在传输的响应不因公钥
移除自动终止，已经传出的字节无法收回；不把这个运行配置操作说成实时回收。
业务成员/下载授权的撤销仍使用独立 D1 事实与现有请求/续传检查。

## 本地验证与证据

`tests/identity-rotation.test.mjs` 通过实际 Worker HTTP 请求证明主体保持、成员读
权限、owner-only 写入、原创建请求的幂等回执、revision 和审计保持。隔离 R2
对象的字节和 etag 在重配置后相同；撤旧后的读写在认证层拒绝，没有落库副作用。
无配置/坏配置期间拒绝创建，恢复后原键仍能重放。成员撤销对新旧 signer 一致。

`tests/identity-config.test.mjs` 验证四把公钥、2048/4096 位验证、非法备用钥、
重复标识/材料、私钥字段、用途、边界、算法混淆、过长请求和恢复。原有
`boundaries.test.mjs`、`catalog.test.mjs` 是直接邻近回归。

初轮暴露的是 Miniflare `setOptions()` 使旧 D1/R2 stub 失效，不是数据损坏。
夹具已在重配置后重新获取 binding，保留同一 persistence 路径、资源名称和
模块，不重新应用 Schema；每次结束关闭自己创建的运行时，状态和证据保留。

证据根目录：`../../linshi/assetlibrary-identity-rotation-20261005`。
补充异常类型 `kid`、2047 位/偶数模数拒绝与实际 4096 位 signer 后，8 个相关
测试文件为 **32 pass / 0 fail / 0 skip**，受测候选 `assetlibrary-p3-T5kmib`。
除了上述身份/目录文件，还包括 `upload-recovery.test.mjs`、`versions.test.mjs`、
`distribution.test.mjs`、`distribution-grants.test.mjs`；正向分发仍是假设准入和
合成扫描事实，不是生产成功分发。最终候选与直接受测结果以该目录
`final-delivery.json` 为准。没有重跑 `.18` 的完整 202 项或浏览器全矩阵；那些结果是先前基线，
不是 `.19` 全套验收。最终交付须核对源输入、受测/交付运行字节和包校验和。

本轮 Biome、TypeScript、UTF-8/有效行数和联网 pnpm audit 通过，audit 报告
`No known vulnerabilities found`。两独立仓库 `git diff --check` 均为 exit 0；
Neuro 对其既有 README 的 LF/CRLF warning 保留，不为本任务修改父仓库。
新增/实质修改的实现：`identity.ts` 44、`identity/keys.ts` 81、测试夹具 176、
身份测试夹具 52、配置测试 115、轮换测试 179 有效行；均小于 500，未申请例外。

## 尚缺的真实身份接入

此前只读检索没有找到可直接用于 AssetLibrary 的 Neuro RS256 Bearer JWT
签发合同；这不证明外部服务不存在。Platform 的 OAuth 登录/内部 account API、
Loom 的 Ed25519 设备证明不是自动可替代的签发接口。已异步询问以下公开信息，
无需提供私钥或访问令牌：

- 已部署签发服务地址、固定 issuer 和 AssetLibrary audience；
- 公开 RSA 公钥/JWKS 及 `kid` 轮换合同；
- 客户端取得短期 JWT 的正式入口和账号授权流程；
- canonical user ID 到 `sub`/`PrincipalRef` 的稳定映射。

运行观测、故障/恢复及合成身份云轮换切片已由后续 `.22` 补齐，见
[P6 云验收与收尾](P6_CLOUD_RECOVERY_VALIDATION.md)。真实账号仍须上述公开签发
合同和实际登录验收，不能以合成 signer、本地数据保持或云配置切换结果替代。
云中撤旧后的读写 401、新钥幂等重放、显式成员撤销后两把 signer 均 404，以及
非法配置 503/恢复均已记录；生效探测有 120 秒上限并关联实际云版本，不承诺
全球瞬时撤钥或终止已认证响应。完整 P5/P6 及延期安全退出条件仍开放。
